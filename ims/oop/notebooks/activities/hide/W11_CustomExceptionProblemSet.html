Custom-Exception Problem Set#

DS212 — Object-Oriented Programming

Assessment: Problem set (with Quiz 3) · Week 11 · CO3

ILO : Design robust classes using exception handling, custom exceptions, and defensive programming.

Overview#

Solve the four problems below. Each problem focuses on one part of robust, exception-aware object-oriented design.

Problem 1 — Designing an exception hierarchy#

An online laboratory reservation system has these failure situations:

  • a student books a computer that does not exist;

  • a computer is already reserved for the requested time;

  • a reservation is outside laboratory hours (7:00–19:00);

  • a student exceeds two reservations per day;

  • the reservation file cannot be read.

  1. Design a custom exception hierarchy (class diagram) with one base exception.

  2. Decide which exceptions should carry attributes (for example, the conflicting time slot) and implement them.

  3. Explain which situations should use a built-in exception instead of a custom one.

Problem 2 — A defensive class#

Implement LabReservations, which uses your exceptions from Problem 1:

  • add_computer(code);

  • reserve(student_id, code, start_hour, hours) that validates every rule and leaves the object unchanged if any rule fails;

  • cancel(student_id, code, start_hour);

  • schedule_for(code) returning the reservations sorted by start time.

Demonstrate every rule being violated once, and show that the object’s state is unchanged after each failure.

Problem 3 — Find and fix the exception-handling problems#

The following code “works” but handles exceptions badly. Identify at least five problems, explain each, and rewrite the code.

class GradeImporter:
    def __init__(self, path):
        self.path = path
        self.grades = {}

    def load(self):
        try:
            f = open(self.path)
            for line in f:
                name, grade = line.split(",")
                self.grades[name] = float(grade)
            f.close()
        except:
            print("error")

    def average(self):
        try:
            return sum(self.grades.values()) / len(self.grades)
        except Exception:
            return 0

    def get(self, name):
        try:
            return self.grades[name]
        except KeyError:
            raise Exception("not found")

Test your rewritten version with: a missing file, a line with a missing comma, a non-numeric grade, an empty file, and an unknown student name.

Problem 4 — Guaranteed cleanup#

Write a context manager class AuditLog that:

  • opens (or creates) a log file in __enter__;

  • lets code inside the with block call log.write(message);

  • in __exit__, writes OK if the block finished normally or FAILED: <ExceptionName>: <message> if an exception occurred, closes the file, and lets the exception propagate.

Show both a successful block and a failing block, then print the log file’s contents.

Reflection#

  • In your own words, when should a method raise an exception, and when should it handle one?

  • Why is except: with no exception type dangerous?
